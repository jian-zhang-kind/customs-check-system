# 需求规格说明书：关务慧眼｜出口货物海关申报自查系统

> 依据：[@docs/handoff.md](handoff.md)、[@docs/竞品分析.md](竞品分析.md)（文内标题为《需求分析_竞品对比》）。  
> 本文只定义需求，不含架构实现与代码。  
> 全部功能边界以交接文档为准，禁止超出已锁定的 MVP。

---

## 1. 一句话产品定位

关务慧眼是面向中小外贸企业的**出口申报前自查工具**，在报关提交前拦截单证不一致、HS 归类错误、实物与申报不符三类风险，减少退税驳回与海关查验处罚；**不是海关监管系统**。

---

## 2. 目标用户说明

调研材料未给出独立职业名称清单。用户划分依据产品定位（中小外贸企业申报前自查）以及现场场景结论（发货前 / 仓库是明确的移动使用时点，且不替代电脑端制单）。经确认：

| 类型 | 角色 | 画像 | 痛点（来自调研证据） | 使用场景 |
| --- | --- | --- | --- | --- |
| 主要用户 | 中小外贸企业关务 / 单证人员 | 负责出口报关制单与申报前复核；企业规模小，缺少专职归类专家；制单仍在电脑端完成 | 报关单、发票、合同等单证一字之差导致退税驳回（单证不一致约占驳回原因 28%）；HS 归类错误、品名不符、数据矛盾高发；归类不熟悉时只得到编码、给不出法规依据 | 报关提交前，在电脑端上传仿真 / 待申报单据，跑「单单相符 + 单证相符」自查，阅读带法规依据的体检报告后再决定是否提交 |
| 次要用户 | 发货前 / 仓库现场核对人员 | 在仓库或装柜现场执行货证核对；使用手机，不替代电脑端制单 | 唛头、包装属法定查验内容；唛头批号须与装箱单批次一致，品名中英文须与装箱单一致；现场缺少自动比对工具 | 装柜 / 发货前用手机拍摄唛头、装箱单，与系统内已录入的申报数据比对唛头、批号、件数 |

**非用户（明确排除）：** 海关监管人员、缉私或风控部门。本产品不做企业团伙风险分析，也不向监管侧输出企业画像。

调研来源（不新增渠道）：海关总署公开处罚案例、税务局退税驳回统计、海关法规文件（《海关进出口货物查验管理办法》、SN/T 行业标准）、市面主流关务工具实测、外贸关务从业者访谈。

## 3. 功能需求清单

优先级约定：

- **P0**：本次必须实现的 MVP，仅 [handoff.md](handoff.md) 锁定的 3 个核心功能及其支撑能力。
- **P1**：增值演示，可选；仅「归类疑难才触发的多模型辩论」。
- **P2**：未来迭代，**本次不实现**。

### 3.1 P0 必须做（MVP）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-P0-01 | **单证交叉核对（单单相符）**：对同一票货物的报关单、增值税发票、装箱单、出口合同做交叉核对。OCR 抽取单据字段，LLM 仅做字段语义对齐，用超图建模多字段勾稽约束网络，由规则引擎校验单据间品名、主体、数量、金额逻辑矛盾，输出可追溯风险项。 | P0 |
| FR-P0-01a | 品名核对：识别跨单据品名表述冲突（调研例：报关单「USB 数据线」与发票「USB 充电线」）。 | P0 |
| FR-P0-01b | 主体核对：识别报关单「境内发货人」与增值税发票「销售方」等主体名称不一致（调研例：仅差「公司」二字导致税务比对失败）。 | P0 |
| FR-P0-01c | 数量勾稽：校验「发票数量 = 装箱单件数 × 每箱数量」及与报关数量的一致性（调研例：申报 113000 盒、实际 30000 盒）。 | P0 |
| FR-P0-01d | 金额逻辑矛盾校验：仅检查单据间金额勾稽是否自洽，不做价格评估、估价或价格异常专项模型。 | P0 |
| FR-P0-02 | **HS 编码与申报要素纠错（单证相符）**：根据品名、材质成分等申报要素，经 RAG 检索海外各国政府官方公开的进口商品法律法规快照，由规则引擎对照申报 HS 给出纠错结论，并附法规原文、法规名称、发布日期、来源链接。独立关务问答不单列，相关问答能力合并本模块。 | P0 |
| FR-P0-02a | 归类必须给依据：报告不得只给编码，必须引用公开法规原文摘录及官方来源链接（调研：错误归类后果严重，竞品也以「给依据」区分）。 | P0 |
| FR-P0-02b | 材质成分作为关键申报要素参与归类校验（调研例：女裤 86% 粘胶纤维 14% 亚麻，错报 6204630000，应归 6204690000）。 | P0 |
| FR-P0-03 | **现场拍照核对（单货相符）**：手机拍摄唛头、装箱单图片，OCR 提取唛头、批号、件数，与系统内报关申报数据比对，现场提示不一致风险。使用时点限定为发货前 / 仓库现场，不替代电脑端制单。 | P0 |
| FR-P0-04 | **自查体检报告**：一次自查输出报告，包含风险等级、风险项、所依据的规则编号 / 勾稽约束、法规摘录。最终风险结论只能由规则引擎给出，禁止大模型直接输出判定结果。 | P0 |
| FR-P0-05 | **仿真演示案例**：提供一份可一键跑通的模拟出口案例（建议合成公开处罚结构：主体差二字、数量勾稽失败、女裤成分归类差错、唛头批号不符）。业务单证全部为模拟仿真样本；法规为官方公开进口法律法规快照。禁止真实企业报关单与海关内部非公开材料。 | P0 |

## 4. 用户故事 User Story

| 编号 | 用户故事 | 覆盖需求 |
| --- | --- | --- |
| US-01 | 作为**关务 / 单证人员**，我希望系统自动交叉核对报关单、发票、装箱单和合同上的品名、主体、数量、金额，以便在提交前发现「USB 数据线 / USB 充电线」这类字面不一致，降低退税因单证不符被驳回的风险。 | FR-P0-01、FR-P0-01a |
| US-02 | 作为**关务 / 单证人员**，我希望系统能识别「有限」与「有限公司」这类主体名称细微差异，以便避免境内发货人与发票销售方比对失败、退税卡两个月。 | FR-P0-01b |
| US-03 | 作为**关务 / 单证人员**，我希望系统按「发票数量 = 箱单件数 × 每箱数量」做勾稽，以便在申报前拦截数量申报不实。 | FR-P0-01c |
| US-04 | 作为**关务 / 单证人员**，我希望系统根据品名和材质成分核对 HS 编码，并给出官方公开进口法规原文及来源链接，以便在不熟悉归类时不只得到一个编码、减少错报子目。 | FR-P0-02、FR-P0-02a、FR-P0-02b |
| US-05 | 作为**发货前 / 仓库现场核对人员**，我希望用手机拍摄唛头和装箱单，自动比对唛头、批号、件数是否与申报数据一致，以便在装柜前发现货证不符，而不是到海关查验才暴露。 | FR-P0-03 |
| US-06 | 作为**关务 / 单证人员**，我希望一次自查得到带风险等级、规则编号和法规摘录的体检报告，以便向老板或申报人解释「为什么不能直接提交」，而不是面对无法追溯的模型结论。 | FR-P0-04 |
| US-07 | 作为**关务 / 单证人员**，当系统判定归类疑难时，我希望可以查看多模型辩论整理出的带引用意见，再由规则给出最终收口，以便在相邻子目、成分跨界这类场景获得可演示的增值依据，而不是把辩论当成日常主流程。 | FR-P1-01 |

## 5. 业务用例

每个 P0 核心功能对应 1 个用例。参与者不含海关监管角色。数据一律为模拟 / 公开摘录。

### UC-01 单证交叉核对（单单相符）

| 字段 | 内容 |
| --- | --- |
| 用例 ID | UC-01 |
| 用例名称 | 申报前单证交叉核对 |
| 参与者 | 主要用户（关务 / 单证人员） |
| 前置条件 | 1. 用户已打开演示系统。2. 已准备同一票货物的模拟报关单、增值税发票、装箱单、出口合同（文件或系统内仿真案例）。3. 禁止使用真实企业报关单或海关内部非公开材料。 |
| 主成功场景 | 1. 用户上传上述单据，或一键加载仿真案例。2. 系统 OCR 抽取各单字段。3. 系统用大模型做字段语义对齐（品名、主体、数量、金额等映射到统一字段），**不对齐结果直接当作风险结论**。4. 系统按超图勾稽模板建立多字段约束（例如发票数量、箱数、每箱数量、报关数量共边）。5. **规则引擎**执行品名、主体、数量、金额硬校验。6. 系统写入自查报告：每条风险含等级、规则编号、证据字段、涉及单据，不含大模型自由判定句作为结论。7. 用户阅读报告，决定修改单据或暂缓申报（申报提交本身不在本系统内完成）。 |
| 扩展 / 异常分支 | A1. OCR 无法抽取关键字段：报告标记「抽取失败 / 字段缺失」，规则引擎按缺失处理，不由模型补造结论。A2. 语义对齐给出多个候选映射：保留候选与对齐记录，最终是否构成风险仍由规则判定。A3. 某类单据未上传：仅对已有单据构图校验，报告列出未参与核对的单据类型。A4. 无矛盾：报告给出通过项及所使用的勾稽规则，仍须可追溯。 |

### UC-02 HS 编码与申报要素纠错（单证相符）

| 字段 | 内容 |
| --- | --- |
| 用例 ID | UC-02 |
| 用例名称 | HS 编码与申报要素纠错 |
| 参与者 | 主要用户（关务 / 单证人员） |
| 前置条件 | 1. 已有模拟报关数据中的品名、材质成分、申报 HS。2. 知识库仅为海外政府官方公开进口法律法规快照（含来源链接、法规名称、发布日期）。3. 独立问答入口不存在。 |
| 主成功场景 | 1. 用户发起自查（可与 UC-01 同一次运行）。2. 系统读取品名、成分等申报要素。3. RAG 检索公开进口法规快照，返回原文块及来源链接。4. **规则引擎**比较申报编码与检索到的条文，输出「相符 / 疑似错报 / 疑难」及法规摘录。5. 非疑难：报告给出纠错结论 + 原文依据后结束（**不调用**多模型辩论）。6. 用户依据条文与来源链接决定是否改码。 |
| 扩展 / 异常分支 | B1. **归类疑难（P1）**：规则引擎标记疑难（例如相邻子目且成分跨过归类界限）后，才可触发多模型辩论；辩论材料必须带引用，**最终判定仍由规则引擎收口**。B2. 辩论关闭或调用失败：主流程仍输出 RAG 条文 + 规则结论，系统不得改为「以模型投票代替规则」。B3. 知识库未命中：报告声明依据不足，不得由大模型编造条文。B4. 用户口头提问关务政策：无独立问答页；仅能依附本模块已检索到的法规块展示，不扩展为通用聊天。 |

### UC-03 现场拍照核对（单货相符）

| 字段 | 内容 |
| --- | --- |
| 用例 ID | UC-03 |
| 用例名称 | 发货前唛头 / 装箱单拍照核对 |
| 参与者 | 次要用户（发货前 / 仓库现场核对人员）；关务人员亦可在现场使用 |
| 前置条件 | 1. 系统内已有该票模拟申报数据（报关单 / 装箱单字段：唛头、批号、件数等）。2. 使用者处于发货前或仓库现场演示情境。3. 可通过手机浏览器拍照或选图，不要求原生 App。 |
| 主成功场景 | 1. 用户拍摄或上传唛头、装箱单图片。2. OCR 提取唛头、批号、件数。3. 字段与系统内申报 / 箱单数据对齐。4. **规则引擎**比对唛头、批号、件数是否一致。5. 现场展示不一致风险（证据为抽取文本 + 系统字段 + 规则编号）。6. 该结果并入或关联同一票自查报告。 |
| 扩展 / 异常分支 | C1. 照片模糊或未拍到批号：报告「现场抽取不完整」，不由模型脑补唛头。C2. 系统内尚无该票申报数据：提示先完成单据录入 / 加载仿真案例，不进入监管查验流程。C3. 仅拍唛头未拍箱单，或相反：对已抽取字段做部分比对，未比对项在报告中标明。C4. 本用例不延伸到外形查验的全部法定项目（如外观残损鉴定）；MVP 只核唛头、批号、件数。 |

## 6. 非功能需求（竞赛项目）

| 编号 | 类别 | 需求描述 |
| --- | --- | --- |
| NFR-01 | 可解释性 | 每条风险必须能追溯到：规则编号、参与勾稽的字段 / 超边、（如涉及归类）法规原文摘录、法规名称、发布日期、官方来源链接。大模型只做语义理解与对齐，**禁止**把模型自然语言直接当作最终风险判定。 |
| NFR-02 | 演示友好性 | 提供简单网页演示；支持一键跑通仿真案例；三个 P0 功能在同一演示界面可区分展示；现场拍照可用手机浏览器摄像头或选图，不强制安装 App；页面文案表述为「申报前自查」，不出现监管、团伙、企业画像用语。 |
| NFR-03 | 数据安全 | 业务报关单据、企业单证只用模拟仿真样本；法规库只用海外政府官方公开进口法律法规。禁止导入真实企业报关单、海关内部非公开材料。超图只表达单据字段勾稽，不存储企业关系网络。 |
| NFR-04 | 运行环境 | 大学生竞赛演示优先轻量化、本地可运行、低部署门槛；不做完整生产级部署（集群、多租户、等保、海关内网对接等）。OCR 选用开源 PaddleOCR（交接已定）。 |
| NFR-05 | 性能（演示级） | 单份仿真案例（数张单据 + 现场照片）在本地演示环境完成一次自查即可用于答辩；不承诺生产并发、海量税则全量检索或实时全国同步。P1 辩论允许明显慢于主流程，且可关闭。 |
| NFR-06 | 判定可信约束 | 硬约束优先；超图仅用于单据字段多对多勾稽约束网络，禁止设计为企业团伙风险网络。 |
| NFR-07 | 法规快照 | 知识库为演示打包时的公开法规快照，不承诺与官方网站实时同步；商用须定期更新。 |
| NFR-08 | 免责声明 | 本系统为竞赛 / 申报前自查演示工具，输出不构成法律意见或正式归类裁定。 |

## 7. 本次版本明确不做的功能（Out-of-Scope）

下列能力即使竞赛评委提问，也不得在本版本设计或实现中加入：

1. 第四个及以上业务功能模块（MVP 只保留单单相符、单证相符、单货相符）。
2. 独立关务问答 / 通用政策聊天机器人。
3. 海关监管系统能力：查验任务分派、企业信用评级、走私线索、企业团伙风险分析。
4. 将多模型辩论作为每票必走的主流程。
5. 由大模型直接输出「高风险 / 允许申报 / 违法」等最终判定。
6. 企业真实报关单据、海关内部非公开材料、真实查验影像的采集与存储。
7. 完整生产级部署与运维（高可用、权限体系、与单一窗口 / 电子口岸生产对接）。
