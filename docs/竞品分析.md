表格



| 发现 | 具体证据 | 对产品的启示 |

| --- | --- | --- |

| 单证信息不一致是退税驳回首因 | 税务局做 "报关单、增值税发票、出口合同、收汇凭证"4 单比对，单证信息不一致占驳回原因 28%，如报关单写 "USB 数据线"、发票写 "USB 充电线" 即被字面驳回 | 直接支撑「多单证交叉核对」核心功能 |

| 一字之差卡退税两个月 | 报关单 "境内发货人" 与增值税发票 "销售方" 仅差 "公司" 二字（"有限"vs"有限公司"），税务比对失败（云南长浩案例） | 演示样例可直接用这类 "低级但高损失" 案例 |

| 数量申报不实高发 | 深圳企业申报出口电子烟 113000 盒，实际仅 30000 盒，多报部分货值约 79 万元 | 数量逻辑校验（发票数 = 箱单件数 × 每箱数）是刚需 |

| 归类错误多因 "不熟悉" | 广州海关案例：当事人因归类知识不熟悉，将 42029200（容器）错报为 56039410（无纺织物） | 归类推荐必须给依据，而非只给编码 |

\## 四、调研结论（对 MVP 的直接影响）



表格



| 结论 | 依据 |

| --- | --- |

| "多单证交叉核对" 和 "现场拍唛头 / 批号核对" 是竞品空白，应作为差异化主打 | 官方工具只查询 / 管制审核，商业工具只做单点查询，无自动比对 |

| 归类、品名、数量是差错高发点，校验规则应优先覆盖这三类 | 退单前两类占 60% 以上，处罚案例高度集中 |

| 手机端场景成立，聚焦 "发货前 / 仓库现场"，不要试图替代电脑端制单 | 法定现场核对货证流程 + 发货前实务核对 |

| 所有结论必须附法规 / 税则原文引用 | 处罚案例显示错误归类后果严重，且竞品都以 "给依据" |

\## 五、MVP 核心功能（基于本次调研锁定，仅保留 3 项）



1\. \*\*单证交叉核对（单单相符，核心）\*\*

OCR 识别多份单据，LLM 做字段语义对齐，使用\*\*超图建模多字段勾稽约束网络\*\*，配合规则引擎自动校验单据间品名、主体、数量、金额逻辑矛盾，输出风险。

2\. \*\*HS 编码 \& 申报要素纠错（单证相符）\*\*

RAG 检索海外各国政府官方公开的进口商品法律法规（非涉密、官方渠道，结果附来源链接），给出归类结果 + 法规原文依据；归类疑难场景启用多模型辩论（增值功能，非主流程）。业务报关单据仍用模拟仿真样本。

3\. \*\*现场拍照核对（单货相符）\*\*

手机现场拍摄唛头、装箱单图片，OCR 提取唛头、批号、件数，与系统内报关申报数据比对，现场提示不一致风险。



> 

> 剔除功能：独立关务问答模块，问答能力合并至 HS 归类纠错模块。



\## 六、产品定位



面向中小外贸企业出口申报前自查，\*\*不是海关监管系统\*\*，目标是在报关提交前拦截单证不一致、归类错误、实物与申报不符的风险，减少退税驳回、海关查验处罚。



\## 七、调研来源说明



数据来源（调研证据，不是系统入库数据）：海关总署公开处罚案例、税务局退税驳回统计、海关法规文件（查验管理办法、SN/T 行业标准）、市面主流关务工具实测、外贸关务从业者访谈。

系统运行时数据：业务单证 = 模拟仿真样本；RAG = 海外政府官方公开进口法律法规快照。禁止企业真实报关单与海关内部非公开材料。
